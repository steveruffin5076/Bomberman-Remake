# Coding Rules

## General
- Prefer simple, maintainable solutions.
- Preserve approved game design.
- Avoid unrelated refactors.
- Keep changes focused on the current milestone.

## Debugging
- Reproduce before changing code when practical.
- Fix root causes rather than symptoms.
- Check for regressions.

## Architecture
- Follow `ai/ARCHITECTURE.md`.
- Flag architectural conflicts instead of silently redesigning systems.

## Testing
- Test the requested behavior.
- Verify important adjacent behavior.
- Record meaningful project-state changes in `ai/CURRENT_STATE.md`.
